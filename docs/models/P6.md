# P6: anonymous player sets + temporal convolution

## Status

**Stop P6 after v1.** Both implementations run end to end, preserve anonymous
slot invariance and keep `J03WQQ` sealed, but neither earns promotion. Encoding
each object trajectory before pooling improves smoothed spellF1 only slightly;
the three-seed gain over P6 v0 crosses zero, macroF1 falls, and P6 remains far
behind P2.

model development; it is not evidence that every possible set-temporal model
would fail.

## What was tested

Both P6 versions use schema `03_ball_shape_extended`, which excludes provider
tags and generated `gtag_*`, plus a separate structured view of anonymous
players and the ball.

- **v0, pooling first:** shared per-player frame encoder, home/away mean pooling,
  separate ball encoder, then a residual TCN and ternary H/A/D head. It has
  111,795 parameters and a symmetric 127-frame window.
- **v1, trajectory first:** the same asymmetric TCN is applied independently to
  every player tracklet and the ball before home/away mean pooling, followed by
  a ternary head. It has 22,611 parameters and uses 75 past plus 25 future
  frames (about 3 s / 1 s at 25 Hz).

The v1 ordering matches the closest direct possession study more faithfully
than v0. Sum/mean pooling and the single ternary head were kept fixed so this
experiment changed one architectural choice. Unit tests verify that permuting
anonymous player slots does not alter predictions.

Scaling is fit from the four training matches only. Missingness remains
explicit. Training uses `labels_raw`; smoother tuning and reporting use
validation `labels_adjusted`. Neither implementation loads the test match.

## Reproduce P6 v1

Run each seed separately:

```bash
python -m pip install -r requirements-p6.txt
python scripts/validate_model_inputs.py
python scripts/train_p6.py \
  --architecture trajectory_first \
  --epochs 6 \
  --chunks-per-match 64 \
  --chunk-frames 512 \
  --batch-size 4 \
  --target-step 5 \
  --learning-rate 0.0003 \
  --seed 7 \
  --run-name trajectory_tcn_seed7
```

Repeat with seeds 17 and 27. Each run writes ignored artifacts under
`outputs/p6/<run-name>/`: model weights, train-only scaler, validation
probabilities, raw/smoothed labels and `meta.json`.

## Experiment chain

| run | one changed choice | spellF1 | macroF1 | decision |
|---|---|---:|---:|---|
| `sum_tcn_schema03_v0` | v0, LR 0.001, 4 epochs | 0.266 | 0.713 | reject |
| `sum_tcn_schema03_lr3e4` | v0, LR 0.0003, 6 epochs | 0.377 | 0.787 | retain as comparison base |
| `trajectory_tcn_seed{7,17,27}` | per-object temporal encoding before pooling | 0.406 mean | 0.771 mean | reject; fails keep rule |

The v0 learning-rate correction established a usable baseline. The v1
architecture test addressed the main mismatch with the direct research, but
did not produce a reliable gain. Attention, nearest-five selection, two-head
output and further optimizer sweeps are therefore not justified on P6 now.

## Candidate-set update — 2026-11-16

The earlier P6 note said P3/P4 were unavailable. That is no longer true:

- PR 13 reports P3 TCN results. Its final documented single-seed model reaches
  0.630 validation spellF1; the later common three-seed comparison reports
  0.637.
- PR 14 reports the P4 bidirectional GRU at 0.710 validation spellF1 / 0.906
  macroF1, ahead of the documented P2 ensemble at 0.668 / 0.899.
- P4's strongest validated contribution is two additional tracker-damaged
  training copies. Its architecture-only advantage is smaller when P2 receives
  the same copies.

These are branch-reported results, not yet an independent audit. Some P2/P3
comparison rows came from one-off scripts that are not committed, and the
Sportec test match has already been scored multiple times for P2. Do not use
that test match for any further selection.

## Decision and next step

1. Keep P6 code as a negative, reproducible research result; do not blend it or
   score it on `J03WQQ`.
2. Audit PR 13 and PR 14 against the common split, no-leak input contract,
   committed reproducibility and keep-rule calculations.
3. Reproduce P4's decisive validation claims, especially the augmented-data
   ablation, before selecting it over P2.
4. Treat all existing test and BAR-ATH values as report-only. Make no more
   architecture, feature, smoother or ensemble decisions from them.
5. If P4 survives audit, freeze P4 and P2 as the candidate pair. P5 should be
   attempted only if it tests a distinct, pre-registered hypothesis rather
   than adding another unconstrained model sweep.
