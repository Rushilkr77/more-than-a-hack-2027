# P2: gradient-boosted trees + Viterbi smoother

```bash
python scripts/build_sportec_bundles.py                  # damaged Sportec bundles + labels (fixed seeds, ~5 min)
python scripts/train_p2.py                               # final model h_sd_win_1_5_15, ~35 s
python scripts/train_p2.py --version v3_jumps            # any variant in VARIANTS (round 3 options in OPTS)
python scripts/train_p2.py --compare v3_jumps h_sd_win_1_5_15   # keep-rule test on saved predictions
python scripts/tune_smoother_p2.py                       # smoother alternatives on saved validation probabilities
python scripts/p2_parity_check.py                        # BAR-ATH input parity (inputs only, no BAR-ATH labels)
python scripts/jitter_parity.py J03WMX J03WOY           # tracker wobble and ball step speed: BAR-ATH vs bundles
python scripts/diagnostics_round1.py --pred outputs/p2/h_sd_win_1_5_15/smoothed --model-only outputs/p2/h_sd_win_1_5_15/raw
```

`scripts/eval_baseline_p2.py`, and this document. The smoother alternatives below are P2's own experiment on the
common smoother; none beat it, so P2 uses the common smoother unchanged.

## Final approach
| | |
|---|---|
| **Model** | sklearn `HistGradientBoostingClassifier`, defaults in `p2_gbt.PARAMS` (500 trees max, lr 0.1, 31 leaves, L2 1.0, early stopping) |
| **Inputs** (`h_sd_win_1_5_15`, 260 columns) | per-frame frame-table columns (`ft.model_columns()`, generated tags dropped), plus for 15 ball, shape, speed and dead-ball columns: past and next mean, past and next std, and next−past difference over 1, 5 and 15 s windows, computed inside each period |
| **Training rows** | the 4 training matches (J03WN1, J03WOH, J03WPY, J03WR9) on `labels_raw`, every 5th frame, plus a home/away-mirrored copy |
| **Early stopping** | validation matches J03WMX, J03WOY |
| **Smoother** | 3-state Viterbi, one switch penalty (20), never across halftime, penalty picked on validation `labels_adjusted` |
| **Training data** | damaged Sportec bundles from the committed `build_sportec_bundles.py`: ball gaps, tracklet breaks, ghosts, speed blanks, tracker ball teleports, smooth tracker error (low-frequency position error plus light output smoothing) |
| **Test match** | J03WQQ, never loaded; scored once at the end of P2–P5 |

**Validation (current bundles, smooth tracker error):** spellF1 **0.664**, macroF1 **0.899**. Per match: J03WMX 0.654,
J03WOY 0.674. For comparison, the organiser baseline scores 0.20–0.24 on the same matches (0.243 on BAR-ATH) and the
round 2 model `v3_jumps` scores 0.624 / 0.886. Keep rule v3_jumps → final: +0.048 [+0.019, +0.082]. On the earlier
white-noise bundles the same model scored 0.678 / 0.903. The drop comes from more realistic data, not a worse model.

### Baseline vs P2 on the same data (`python scripts/eval_baseline_p2.py`)
The organiser baseline (nearest-player vote, fixed ±50 frames, not tuned) is scored on exactly what P2 sees.

Each cell is spellF1 / macroF1. "Raw" = per-frame output before any smoother (baseline: window 0; P2: argmax), so
P3–P5 can compare their model-only output as well as their smoothed output.

| data | baseline raw | baseline smooth50 | P2 model only | P2 + common smoother |
|---|---|---|---|---|
| Sportec J03WMX (damaged bundle, `labels_adjusted`) | 0.045 / 0.429 | 0.235 / 0.451 | 0.326 / 0.906 | 0.654 / 0.907 |
| Sportec J03WOY | 0.045 / 0.430 | 0.202 / 0.447 | 0.327 / 0.892 | 0.674 / 0.891 |
| BAR-ATH public 5 min (17 possessions, inference only) | 0.038 / 0.597 | 0.326 / 0.621 | 0.270 / 0.827 | 0.594 / 0.830 |

- Smoothing leaves macroF1 at ~0.90 and roughly doubles spellF1 (0.33 → 0.65–0.67). Without it P2 makes ~900–1,000
  possessions where there are ~314. The script prints every row above.

- On Sportec the baseline is the comparison for 0.664: about +0.44 spellF1. (The full-match BAR-ATH baseline is 0.243.)
- BAR-ATH 5 min: P2 beats the baseline and keeps the ordering, but 0.594 is below the Sportec 0.65–0.67. With 17
  possessions one missed spell moves spellF1 by several points, so this is a sanity check, not a score. Nothing was
  tuned on it (risk 3).

### Why this approach
- **Highest validation spellF1 among everything tried, with the best macroF1.** macroF1 is the tie-break. That held on
  both data versions. On the current bundles: h_sd_win_1_5_15 0.664 / 0.899, h_sd_minleaf200 0.651, g_win_std_diff
  0.649 / 0.895, g_win_1_5_15 0.628, v3_jumps 0.624 / 0.886. Against g_win_std_diff (120 inputs) the gain is +0.012
  [−0.009, +0.033], a statistical tie. Under the strict keep rule the simpler set would win; the team criterion is the
  highest spellF1 (macroF1 tie-break), and g_win_std_diff is the fallback if the 1 and 15 s windows prove fragile.
- **The gain is about time, not tree tuning.** All tree settings tied (round 3). What helped was telling each frame what
  happens around it: how much the ball, players and shape move or change over the last and next 1, 5 and 15 s. That's
  the information that separates a real possession change from a flicker, which is what spellF1 scores.
- **Same-sized gains on both validation matches,** so not one match carrying it.
- **Simple and fast:** about 35 s to train, no extra installs, and the same smoother as P3–P5.

### Keep rule (every decision below)
Split the validation frames into 97 two-minute chunks, compute the spellF1 difference per chunk, and bootstrap 2,000
times. **Keep** a change only if the whole 95% interval is above 0. A tie goes to the simpler option.

## Risks against the final evaluation (BAR-ATH, private full-match ground truth, spellF1 then macroF1)
1. **Validation optimism.** About 30 keep-rule decisions across rounds 1–3 and the smoother were all made on the same 2
   validation matches, so 0.664 is optimistic. At 95%, about 1 in 20 tests passes by chance. The test match J03WQQ
   gives the honest number, once, at the end of P2–P5.
2. **Damaged Sportec vs BAR-ATH's tracker** (inputs only, no BAR-ATH labels). Before and after the tracker-error fix:

   | measure | BAR-ATH | white-noise bundles (before) | current bundles |
   |---|---|---|---|
   | player path wobble, median second difference of x | 0.0011 m | 0.18–0.21 m | 0.0010–0.0011 m |
   | ball median step speed (visible, consecutive frames) | 5.1 m/s | 6–7 m/s | 1.1–3.9 m/s |
   | BAR-ATH frames outside Sportec p1–p99, mean / features > 10% | | 3.7% / 19 | 2.4% / 4 |
   | ball visible when players are slow (< 0.8 m/s) / fast (> 2.5 m/s) | 14% / 90% | ~57% / ~63% | unchanged |

   - **What's left:**
     - The 1 s variation of team speed is lower on BAR-ATH (the 4 features above 10% are `*_speed_ms_*sd1s`).
     - The ball steps are slower in our bundles.
   - **The ball gap is not jitter.** Within each player-speed band, ball step speed already matched BAR-ATH. The gap
     comes from *when* the ball is hidden: BAR-ATH's tracker loses it mostly in calm play, ours almost uniformly. So our
     visible frames include more still balls. Fixing that would mean copying BAR-ATH's missing-frame pattern (risk 3),
     so it stays a known difference.
   - **Expected effect:** BAR-ATH can look slightly "calmer" than training on these fields. Calm is a dead-ball cue, so
     the likely failure is too many D frames or late possession starts. The output shape on BAR-ATH (no labels) is
     plausible: 276 possessions, 13.3 s mean length, D/H/A 42/36/22%, confidence 0.91 vs 0.92 on Sportec.
3. **We deliberately don't fit the damage to BAR-ATH.** We tried calibrating it (smoothed tracker paths, ball gaps placed
   in calm play) and reverted it. Matching BAR-ATH's numbers and its pattern of missing frames would make BAR-ATH a tuning
   target, against "BAR-ATH is inference only". It would also teach P2–P5 one fixed tracker personality: for example, a
   fixed rate of "ball hidden means dead ball" (A3 measured 57–80% of D frames hidden vs ~20% of H/A frames). The
   evaluation is 95% unseen, so the training data should cover broad tracker behaviour, not copy one match.
   - **"Trackers smooth their output"** was then added as a mechanism, with wide ranges chosen once and per-match
     variety (see below).
   - **"Trackers lose the ball at stoppages"** is deliberately not added: it can only be specified by copying BAR-ATH's
     visibility pattern.
4. **Labels:** `labels_raw` comes from DFL's own possession feed. The organiser's possession grain is approximated by
   `labels_adjusted` (merges spells under 2 s with no control event), and that is the only place the smoother penalty is
   tuned.
5. **Not covered by P2:** forcing D on BAR-ATH pre-kickoff frames (E1) is a separate post-processing step.
   Metrica's Smart Tagging is not used here; it's a later, BAR-ATH-only step.

## What we tried

### Round 1: baseline (bundles without teleports)
| version | output | spellF1 | macroF1 | spells (true 314–315) |
|---|---|---|---|---|
| v0 per-frame columns (58) | model only / smoothed (penalty 40) | 0.104 / 0.554 | 0.851 / 0.861 | 2,636 / 212 |
| v1 + past/next 5 s means (88) | model only / smoothed (penalty 10) | 0.199 / 0.633 | 0.886 / 0.889 | 1,559 / 265 |

Smoothing does most of the work at this stage (D7). Permutation importance: ball range over 1 s, team speed, and the

Not tried: XGBoost / LightGBM. Both need libomp (a system install), they're the same model family, and the tree-setting
changes here were all within noise.

### Penalty sweep (final model, current bundles; `meta.json` `penalty_curve`)
Mean validation spellF1 against `labels_adjusted` for the common smoother's single switch penalty (nats per label
change). 0 = plain argmax.

| penalty | 0 | 2 | 5 | 10 | **20** | 40 | 80 | 160 |
|---|---|---|---|---|---|---|---|---|
| spellF1 | 0.327 | 0.613 | 0.643 | 0.653 | **0.664** | 0.641 | 0.601 | 0.528 |

Too low leaves flicker (hundreds of extra spells), too high merges real possessions. 20 is the peak and the grid's
middle, so the choice is not an edge effect. The other penalty variants follow.

The remaining errors are in the per-frame probabilities, not the decoder.

### Damage recalibration toward BAR-ATH (tried, reverted)
- **Tried:**
  - Gaussian-smoothed player and ball paths with low-frequency position error. Player jitter then matched BAR-ATH
    (0.0010 vs 0.0011 m).
  - Ball gaps placed in calm play and ended when play resumed. Ball visibility per player-speed band then matched.
- **Result:** BAR-ATH input parity improved (features > 10% outside: 19 → 4), and the final model still beat v3_jumps on
  that data (0.662 vs 0.618, +0.044 [+0.014, +0.080]).
- **Why reverted:**
  - The ranges were fitted to BAR-ATH's numbers and its missing-frame pattern (risk 3).
  - It produced a strong fixed hidden-ball → dead-ball skew (A3).
  - Its validation score was lower than the committed damage.
- The measurements are kept as risk 2.

### Smooth tracker error (adopted, current bundles)
- **Mechanism:** a real tracker's position error drifts slowly and its output is smoothed. Independent per-frame noise
  makes every path shake about 100× more than a smoothed tracker.
- **Change** (`TRACKER_RANGES` in `build_sportec_bundles.py`, own random stream seed + 2, so all other damage is
  byte-identical, and gap placement is untouched):
  - player error keeps its sd but is low-frequency (correlation 0.3–2 s);
  - Gaussian output smoothing of 1–4 frames on player positions and speed;
  - ball error sd 0.05–0.4 m, correlated over 2–10 frames, and ball paths smoothed 1–4 frames.
- **How the ranges were set:** wide, chosen once from the mechanism, not iterated against BAR-ATH.
- **Checks:**
  - Player wobble lands at BAR-ATH's level on all matches.
  - BAR-ATH input parity improves (features > 10% outside: 19 → 4; mean outside 3.7% → 2.4%).
  - Leak markers stay clean: A3 hidden-ball skew 0.02–0.06; A6 accuracy hidden 0.81 vs visible 0.89–0.91.
  - The model ranking is unchanged (see "Why this approach").
- **Note:** the round 1–3 numbers in the tables above were measured on the earlier white-noise bundles. Only the
  candidates listed in "Why this approach" were retrained on the current bundles.
